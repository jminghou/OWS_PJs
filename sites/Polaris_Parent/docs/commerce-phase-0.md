# 階段 0：共用交易與資格骨架

更新：2026-10-14。狀態：交易骨架、帳號綁定啟用碼、歷史訂單回填、外部查證帳本及單份數位報告的外部契約轉換已實作，尚未部署／套用正式 migration，也未回填或匯入正式資料。操作與限制見 [啟用碼說明](commerce-activation.md)、[歷史回填說明](commerce-backfill.md)、[外部訂單查證說明](commerce-intake.md)、[外部契約轉換說明](commerce-contract-binding.md)。

## 這一批能驗收什麼

在測試環境完成 migration 0010，設定 `COMMERCE_FOUNDATION_ENABLED=true` 後，新建官網報告與加購訂單會記錄成交契約。人工核款在同一個資料庫交易內完成付款、資格發放及報告任務關聯；其中任何一步失敗，整筆交易回滾。

- 後台「報告收款」的訂單詳細資料可展開成交明細、來源、資格與任務。
- 成交快照記錄金額、幣別、數量、計價組成及可用的客製選項。之後修改商品設定不改變已買權利。
- 買同一份書的三本印刷品，記為一組製作資格、三份印刷；加購金額不再因數量乘算而重複。
- 報告交付、書籍確認／送印／送達、專人解讀安排／完成會使用並更新原本的資格與任務。
- 取消實體書只撤銷書籍資格，保留同張訂單的數位報告權利；登錄退款金額不得超過應退金額。
- 核款以訂單列鎖串行化，資料庫唯一約束阻止重複資格／任務；舊的核款 API 第二次確認仍回傳 409。
- 新功能預設關閉。沒有版本標記的舊訂單保持既有流程，不自動補發資格。

## 資料結構

沿用既有 `orders`、`order_items`、`payment_attempts`、報告／書籍／解讀工作資料；新增五張本站擁有的 `shop` 資料表，未更動共用資料表定義。

| 新表 | 責任 |
| --- | --- |
| `commerce_sources` | 官網來源、商店識別、外部訂單編號預留欄位與契約版本；外部編號以渠道＋商店為唯一範圍 |
| `commerce_lines` | 每個品項的成交金額、計價數量、印刷份數、計價組成、資格條件快照 |
| `commerce_entitlements` | 每份權利的持有人、操作者、狀態及成交時權限 |
| `commerce_tasks` | 每份資格唯一對應既有履約工作，防止重試產生另一份製作 |
| `commerce_events` | 建單、付款、發放、開始、完成、撤銷的事件紀錄及可提供的操作人 |

資格狀態：`available → in_use → completed`；未完成資格可撤銷為 `revoked`。付款重試不能復活已撤銷權利。數位報告更正上傳沿用同一履約工作，不額外消耗資格。

目前解讀沿用既有的一組預約／工作資料：購買兩次會有兩份資格，但兩份資格共同對應既有解讀工作，完成動作會一起完成。逐次預約與逐次核銷尚待設計。

持有人及操作者目前都設為購買會員。欄位已分開，第二批啟用碼也限此會員兌換，尚未開放轉贈、代操作或代理授權 API。成交快照由服務建立且不提供修改 API，尚未加入資料庫禁止 UPDATE 的機制。

## 啟用與舊資料處理

1. 先在測試環境備妥既有 migration 至 0009 與身分 schema，再執行 0010。正式資料庫尚未執行。
2. 保持開關關閉，確認舊訂單瀏覽及原流程正常。
3. 在測試環境開啟開關，以全新草稿分別驗收數位、實體、加購與解讀訂單。
4. 核款後於後台確認資格，驗收交付、設計、取消、退款及重複請求。
5. 舊訂單先用 blueprint CLI `report_orders commerce-preview --order-no <編號>` 產生唯讀待審清單；也可省略編號。CLI 本身不補發權利，不使用今日商品設定推算歷史權利。
6. 第三批新增詳細盤點 CLI `report_orders commerce-backfill-preview` 與後台逐筆審查／套用工具。先確認付款、歸屬及既有履約狀態，再套用核准計畫；矛盾或缺少證據的訂單維持阻擋，沒有批次強制發放功能。

關閉開關只停止替新訂單建立契約；既有版本 1 訂單仍維持資格檢查。開啟後若需回退，保留包含契約支援的程式與資料表並關閉開關；不能直接退到完全不認得契約的舊程式。0010 的 downgrade 僅允許五張新表皆為空時執行。

## 驗證

測試均不載入正式 app／`.env`，不連真實排盤、寄信或正式資料庫。

- 新資格整合測試 9 項：付款快照、重複核款、加購份數、取消退款、唯一任務、交易回滾、資料庫唯一約束、開關與舊資料、會員隔離，以及完整履約流程（部分合併於同一測試）。
- 既有建單、實體、設計及交付回歸測試 52 項。
- `backend/tests/check_commerce_postgres.py`：一次性本機 PostgreSQL 18 叢集測試 migration 升級／空表回退／再升級、ORM 欄位一致性、真正並行核款與有資料時拒絕刪表。完成自動停止及清除叢集；Windows 使用無視窗程序。
- 前端 `tsc --noEmit --incremental false` 通過。2026-10-15 已完成外部人工查證至單份數位報告交付的隔離瀏覽器驗收，含證據作廢阻擋；範圍、證據與整合環境待驗項目見 [操作驗收報告](commerce-acceptance.md)。

從本站目錄執行 Python 測試時，把 `TMP`／`TEMP` 設在可寫的測試目錄，避免 Windows sandbox 系統暫存目錄權限問題。新測試入口：`backend/tests/test_commerce_foundation.py`；既有測試位於 repo 根目錄的 `tests/test_report_{orders,physical,design,delivery}.py`。

## 階段 0 後續工作

本批是官網交易的第一條完整路徑，並不代表全階段完成。接下來應完成：

1. 已完成：舊資料唯讀詳細盤點與受控逐筆回填工具。後續：在核准環境盤點真實舊資料、確認例外與逐筆驗收；未查證的歷史交易不發資格。
2. 已完成：帳號綁定啟用碼的發放、兌換、到期、撤銷、補發及防重複。後續：外部訂單驗證後發碼、轉贈／代理授權；目前啟用碼只領用既有已付款資格。
3. 已完成：[渠道與查證帳本](commerce-intake.md)，以及 [單份數位報告的商品對應、契約轉換與資格發放](commerce-contract-binding.md)。查證與發放是兩個獨立核准步驟，外部認列不建立官網付款紀錄。證據作廢會阻擋後續履約。後續：實體組合、會員自助領用、外部退款／撤銷例外處理與測試環境驗收。目前沒有 Etsy、Creema、idus 串接，也沒有認定其允許啟用碼流程。
4. 真正的外部派工與通知 outbox／重試工作者。本批任務是持久化工作關聯，報告仍停留既有 `handoff_status=pending` 邊界，不能宣稱已送出外部製作。
5. 幣別最小單位／定價／付款供應商轉接。目前明確只允許 TWD，尚未實作線上收款商通知與對帳。
6. 逐次解讀核銷、細部稽核角色、營運操作畫面及測試環境視覺驗收。

書籍的打樣確認政策仍沿用既有設定，本批沒有改成強制打樣後才可送印。
