# 實作計畫：實體書加購、客製與送印前確認

狀態：草案 v2，待確認（2026-10-09）
相關文件：[membership-v2-architecture.md](membership-v2-architecture.md)、[membership-v2-ziwei-contract.md](membership-v2-ziwei-contract.md)

## 1. 要做到的事

1. **事後加購**：買了數位版、付款完成後，會員可以隨時補買實體書，可填數量。
2. **實體書客製**：封面印名字、扉頁贈言、封面款式／配色、裝訂／規格、加入自己的照片頁或文字頁。
3. **內容調整**：會員看打樣後提出修改意見，由紫微編輯修改後重新出打樣。
4. **送印前確認**：會員在線上看完整的打樣 PDF，按「確認送印」後才能送印。修改次數不限，每一版都留紀錄。
5. **送印前可取消**，已付款的由管理者人工退款並在後台登錄。
6. **出貨管理後台**：從打樣、送印到物流單號、出貨通知，一頁管理。

第 2 到第 5 點適用**所有實體書**：下單就選實體書版的訂單，和事後加購的訂單，都用同一套流程。

## 2. 已確認的決定

| 項目 | 決定 |
|---|---|
| 加購價 | 已含運費，不另收運費 |
| 加購期限 | 沒有期限 |
| 數量 | 可以不止一本，能填數量；同一份報告可以多次加購（例如之後再多買幾本送人） |
| 取消 | 送印前可以取消 |
| 送印檔 | 先用「後台清單＋人工通知紫微」 |
| 出貨管理後台 | 這次一起做 |
| 客製選項 | 封面印名字、扉頁贈言、封面款式／配色、裝訂／規格、照片頁／文字頁 |
| 內容調整 | 看打樣後提出修改意見，由編輯修改；可加入自己的照片或文字頁 |
| 打樣確認 | 線上看打樣 PDF → 確認送印或提出修改；不限修改次數 |
| 適用範圍 | 所有實體書 |

## 3. 會員看到的流程

```
買實體書（下單選實體書版，或之後在訂單頁加購）
  ├─ 下單時：選規格（影響價格）、數量、填收件資料 → 付款
  ↓
付款確認後 → 訂單頁出現「實體書內容設定」
  ├─ 封面名字（預設帶命主稱呼）、封面款式、扉頁贈言
  └─ 照片頁／文字頁：上傳照片＋說明文字、或寫一頁文字
  ↓ 送出設定（送出後鎖定；要改請在打樣階段提出）
編輯製作打樣（數位報告還沒完成的話，會等報告完成）
  ↓
訂單頁出現「打樣確認」：線上看完整 PDF
  ├─「確認送印」→ 鎖定，進入送印
  └─「我要修改」→ 寫修改意見 → 編輯改完出下一版 → 再確認（不限次數）
  ↓
送印 → 已出貨（附物流單號）→ 已送達
```

- 在「確認送印」之前，會員都可以取消這本實體書。
- 規格在下單時就決定，因為它影響價格。其他客製內容在付款後才填，下單時不必一次填完。

## 4. 規則

| 項目 | 規則 |
|---|---|
| 加購資格 | 原訂單已付款，且是本人。原訂單是數位版或實體書版都可以加購，例如實體書版的人想多買幾本 |
| 價格 | 一本＝加購價＋所選規格的加價＋照片頁／文字頁加價（如果後台有設定）；總額＝一本的價格×數量。後端在建單當下計算並存入訂單，之後調價不影響已成立的訂單 |
| 下單選實體書版 | 一本＝數位版售價＋加購價＋規格加價（＝現在的實體書售價邏輯）；數量固定 1 本，要多本請事後加購 |
| 客製設定送出期限 | 不限，但編輯要等設定送出才開始做打樣 |
| 取消 | 「確認送印」前可取消。事後加購的訂單：整張取消，已付款的全額退款。下單時選實體書版的訂單：改成數位版，退還差價 |
| 退款 | 人工轉帳退款；管理者在後台登錄退款金額、日期、備註，系統寄信通知會員 |
| 逾期未付款 | 與一般訂單相同，自動取消 |

## 5. 資料結構（需要 migration）

已經有的、可以直接用的：
- 訂單項目的 `kind`（purchase／addon）、`parent_item_id`、`quantity`。
- 出貨表 `shop.shipments`。

要新增（放在 Polaris 站台的 migration 鏈，依本機優先流程先在本機驗證）：

| 表 | 用途 | 主要欄位 |
|---|---|---|
| `shop.report_print_jobs` | 每個實體書訂單項目一筆，管實體書的生命週期 | `order_item_id`（唯一）、`status`、`spec`（規格快照）、`options`（封面名字／款式／贈言）、`pages`（照片頁與文字頁）、`customized_at`、`approved_at`、`approved_proof_id`、`cancelled_at`、`refund_amount`、`refunded_at`、`refund_note` |
| `shop.report_print_proofs` | 每一版打樣一筆 | `print_job_id`、`version`、`file_key`（私有儲存）、`uploaded_by`、`member_decision`（approved／changes_requested）、`member_comment`、`decided_at` |
| `shop.report_print_assets` | 會員上傳的照片 | `print_job_id`、`file_key`、`content_type`、`bytes`、`created_at` |

`report_print_jobs.status` 的狀態：

`awaiting_payment` → `awaiting_customization`（待會員填設定）→ `awaiting_proof`（待出打樣）→ `proof_ready`（待會員確認）⇄ `changes_requested`（待編輯修改）→ `approved`（已確認、待送印）→ `printing` → `shipped` → `delivered`

另有 `cancelled`。物流資訊（物流業者、單號）沿用 `shipments`。

## 6. 私有檔案儲存（需要你在 GCP 操作）

打樣 PDF 與會員照片含個資，**不能放在現在的媒體庫**；媒體庫的檔案是公開網址。

- **正式站**：新增一個私有 GCS bucket，由後端產生 5–10 分鐘有效的簽名網址，只有訂單本人與管理者拿得到。需要你：
  1. 在 GCP 建立 bucket。
  2. 給後端的服務帳號讀寫權限。
  3. 在 Railway 設定環境變數 `PRIVATE_GCS_BUCKET_NAME`。
- **本機**：存在本機私有資料夾，經由需要登入的 API 下載。
- 上傳限制：照片只收 JPG／PNG／HEIC，單張 20 MB；打樣只收 PDF，單檔 100 MB。

## 7. 程式改動

### 7.1 後端（`sites/Polaris_Parent/backend/extensions/report_orders/`，必要時拆出 `report_print/` 模組）

- **加購**：資格判斷、建立加購訂單（數量、規格、收件資料）、價格計算。用 `submission_key` 防止重複送出。
- **下單選實體書版**：建單時一併建立 print job、帶入規格。
- **付款成功**（`mark_paid`）：print job 進入「待填設定」。事後加購不建立新的報告製作單。
- **會員 API**：
  - 讀取／送出客製設定。
  - 上傳／刪除照片。
  - 取得打樣簽名網址。
  - 確認送印、提出修改。
  - 取消實體書。
- **管理 API**：
  - 出貨管理清單（依狀態篩選）。
  - 上傳打樣。
  - 標記送印、登錄物流（寄出貨通知）、標記送達。
  - 登錄退款。
  - 匯出客製資料給紫微編輯。
- **商品設定**：沿用數位版的 attributes。後台「實體書設定」分頁存放：
  - 規格清單（名稱、加價）。
  - 封面款式清單（名稱、示意圖）。
  - 贈言字數上限。
  - 照片頁／文字頁的上限與每頁加價。
- **通知信**：
  - 寄給會員：打樣已完成請確認、已出貨、已取消／已退款。
  - 寄給管理者：會員送出設定、會員提出修改、會員確認送印。
- **測試**：補在 `tests/test_report_orders.py` 或新的測試檔，涵蓋：
  - 加購資格。
  - 價格（數量×規格×頁數）。
  - 狀態轉換的合法性，例如沒確認不能送印、確認後不能取消。
  - 擁有權。
  - 退款登錄。
  - 重複送出。

### 7.2 前台（`sites/Polaris_Parent/frontend/`）

- **會員中心「我的報告訂單」清單**：目前沒有，要新增。
- **訂單頁**：依狀態顯示「加購實體書」→「實體書內容設定」→「打樣確認」→「出貨進度」→「取消實體書」。
- **加購頁**：數量、規格、收件資料、金額確認、交易政策。
- **實體書內容設定**：封面名字、款式（附示意圖）、贈言（字數提示）、照片頁與文字頁（新增、排序、刪除；手機可直接拍照上傳）。
- **打樣確認**：開啟 PDF（手機也能看）、歷次版本與修改意見紀錄、確認送印要二次確認、提出修改要填意見。
- **下單時選實體書版**：預覽頁加上規格選擇。
- **交易政策頁**：補充「實體書送印前可取消、確認送印後不受理取消」。政策版本號要升版。

### 7.3 後台

- **產品 → 數位版「實體書設定」分頁**：由現在的「加購實體書」分頁擴充，管理是否開放、加購價、規格、封面款式、贈言與頁面設定。
- **新頁面「實體書出貨」**，分成這幾個頁籤：
  - 待填設定。
  - 待出打樣：可看完整客製內容、下載照片、一鍵複製給紫微編輯。
  - 待會員確認。
  - 待修改：顯示修改意見。
  - 待送印。
  - 印製中：登錄物流後寄出貨通知。
  - 已出貨。
  - 已取消／待退款。
- **「報告收款」頁**：加購訂單加上標籤與原訂單號。

### 7.4 紫微（人工銜接）

紫微 repo 這次不改。流程：
1. 管理者在「待出打樣」清單看到新案件，把客製資料與照片交給紫微編輯。
2. 編輯排出打樣 PDF 後，交回管理者上傳到後台。
3. 會員確認後，送印檔交給印刷廠。

日後紫微交接自動化時，再把這段改成 API。

## 8. 分階段交付

每一階段都可以單獨上線，前一階段不依賴後一階段。

| 階段 | 內容 | 預估 |
|---|---|---|
| 1 | 事後加購（數量、規格與價格）、會員「我的報告訂單」、出貨管理後台基本版（送印、物流、出貨通知）、送印前取消與退款登錄、資料表 migration | 3–4 天 |
| 2 | 實體書內容設定（封面名字、款式、贈言、照片頁／文字頁）、私有檔案儲存 | 3 天 |
| 3 | 打樣確認流程（上傳打樣、會員確認或提出修改、版本紀錄、未確認不能送印）、通知信 | 3 天 |
| 4 | 交易政策更新、端到端測試、正式站 migration 與上線 | 1 天 |

合計約 10–11 個工作天。正式站要等階段 1 的 migration 在本機驗證過才跑。

## 10. 選項與計價（第三輪確認，2026-10-09）

取代前面「加購價＋規格加價＋每頁加價」的算法。以下名稱與價格都做成後台可設定，數字是目前的定價。

| 區塊 | 選項 | 價格 | 收費方式 |
|---|---|---|---|
| 一、規格（必選一個） | 平裝／精裝（銅西卡紙質）／精裝（薄紙版） | −300／原價／原價 | 只影響第一本 |
| 二、數量 | 第一本 1,200；第二本起每本 600 | — | 每本內容相同、寄同一地址；含運費 |
| 三、特殊客製（選填，預設收合） | 客製封面（自備圖片；如需另外設計，費用另計） | +300 | 一張訂單收一次 |
| | 解鎖內容文字修改 | +500 | 一張訂單收一次；打樣時也能補買 |
| | 修改及置入指定圖片 | +500 | 一張訂單收一次 |
| | 加入自己的指定頁面 | 每個跨頁 +300 | 依跨頁數，一張訂單收一次 |
| 四、專人解讀（選填） | 30 分鐘 | 1,500／次 | 可買多次；任何報告訂單都能加購（含只買數位版），也可單獨加購；付款後以 Email 或電話約時間 |

例：精裝（銅西卡）2 本＋解鎖文字修改＋2 個跨頁＋解讀 1 次＝1,200＋600＋500＋600＋1,500＝4,400。

其他規則：
- 沒買「解鎖內容文字修改」的人，打樣時只能免費回報錯字、稱呼或資料錯誤；想改寫內容可在打樣頁補買（會產生一筆補款訂單）。
- 封面款式（後台清單，預設兩種）仍是免費選擇；「客製封面」是改用自己的圖片。
- 下單時選實體書版：訂單金額＝數位版售價＋上面的實體書金額。

### 對程式的影響（階段 1 需要改寫的部分）

1. **設定結構**：「實體書設定」分頁改成：第一本價格、第二本起價格、規格清單（加減價可為負數）、特殊客製清單（每項：名稱、說明、價格、一次性或依數量）、專人解讀（價格、分鐘數、每次最多幾次）。取代原本的加購價、每頁加價、頁數上限。
2. **計價**：後端改為「第一本（含規格）＋第二本起×數量＋客製一次性費用＋解讀」，訂單快照記錄每一項。
3. **一張訂單多個品項**：實體書與專人解讀要同一次付款，訂單需要支援多個品項。目前程式假設一張訂單只有一個品項（訂單摘要、通知信、後台列表），要一起調整。
4. **專人解讀的後續管理**：新增解讀紀錄（待聯絡／已約時間／已完成／已取消），後台加「專人解讀」清單；取消與退款規則見下方待確認。
5. **補購文字修改**（階段 3）：打樣頁可補買，產生一筆小額補款訂單，付款後解鎖。

預估在原本 10–11 天之外，再增加約 3–4 天。

### 第五輪：內容設計提前到付款前（2026-10-10）

使用者決定：實體書內容在**選完規格之後、付款之前**就設計，並即時預覽，讓客人在決定付款前就知道自己會收到什麼。取代第 3 節「付款後才填內容」的流程。

調整後的流程（事後加購與下單選實體書版相同）：

1. 選規格、數量、特殊客製、專人解讀（決定價格）
2. **設計你的書**：封面名字、封面款式（或上傳客製封面）、扉頁贈言、指定圖片、指定跨頁內容；上方即時預覽封面、扉頁與跨頁
3. 收件資料 → 同意交易政策 → 送出訂單（設計內容跟著訂單送出）
4. 付款 → 確認收款
5. **付款後最後確認內容**：顯示預覽與檢查清單（未上傳完的項目用紅字提醒），還能修改；按「確認內容，開始製作打樣」後鎖定
6. 打樣確認 → 送印 → 出貨

對程式的影響：
- **設計草稿**：付款前的內容要存在後端（新表，綁會員；建立訂單時連到該實體書），不再只存在瀏覽器。照片上傳在付款前就會發生，所以**私有檔案儲存要在這一步之前就緒**。
- **即時預覽**：前端依封面款式、名字、贈言、上傳圖片畫出書封與內頁縮圖。
- **未付款的上傳檔**：訂單逾期取消或草稿放棄後，照片在一段時間後自動刪除。
- **階段順序**：「設計你的書」原本在階段 2（付款後），現在變成購買流程的一部分，要和階段 1 改寫（新算法）一起做，才能完整走完購買流程。

### 第六輪：設計頁改為「整本書預覽＋頁面標註」（2026-10-10，參考 Wonderbly）

「設計你的書」不是只有封面與贈言的小預覽，而是：
- **整本書翻頁預覽**：用客人已拿到的數位版完整 PDF，一次看一個跨頁；下方縮圖列可跳頁，有標註的頁面顯示記號。
- **直接在書上填寫**：翻到封面填名字、選款式或上傳客製封面；翻到扉頁寫贈言；翻到指定跨頁上傳照片與文字。預覽即時更新。
- **每一頁都能提出修改**，三種類型：改寫文字（需「解鎖內容文字修改」）、換成指定圖片（需「修改及置入指定圖片」）、回報錯誤（免費）。選到需要特殊客製的類型但還沒買，就提示加購並一鍵加入。
- **修改清單**：彙整所有標註（頁碼、類型、內容、附圖），可刪除或點頁碼跳回該頁。
- 不做逐頁即時改字；實際印刷版由你依修改清單排版，再請客人確認打樣。

對程式的影響與前提：
- **需要數位版 PDF 能在網站上讀取**：預覽頁要能取得這份報告的完整 PDF 並轉成頁面圖片。目前數位版交付（紫微上傳成品 PDF、網站提供下載）還沒有做，這是此功能的前置工作。
- 設計草稿要存：封面設定、贈言、標註清單（頁碼＋類型＋文字＋附圖）、上傳的照片。
- 標註清單會跟著訂單送到你的「實體書出貨 → 待出打樣」，排版時對照。

已確認（第六輪）：

| 問題 | 決定 | 做法 |
|---|---|---|
| 報告還在製作中能否加購 | 可以買，設計稍後 | 先選規格、付款；報告完成後才開放「設計你的書」，並寄信通知客人來設計 |
| 第一次下單就選實體書版 | 報告完成後再設計 | 下單時選規格、數量、客製項目（可先填封面名字與贈言）；報告完成後寄信邀請用整本預覽標註修改，再進入打樣 |
| 指定跨頁放在哪裡 | 客人自選位置 | 在預覽中翻到想放的地方，按「在第 N 頁後面插入」；可移到別的位置；未選位置的跨頁會提醒 |

因此流程分成兩種時機，但使用同一個設計頁：
- **報告已完成時加購**：選規格 → 設計你的書（整本預覽）→ 收件 → 付款 → 最後確認 → 打樣。
- **報告未完成時加購／首購就選實體書版**：選規格 → 收件 → 付款 →（報告完成，寄信通知）→ 設計你的書 → 打樣。

## 11. 私有 bucket 設定步驟（階段 2 前完成）

已用唯讀指令核對（2026-10-09）：
- GCP 專案：`polarisparent`。
- 現有 bucket：`polarisparent_pic`（US，公開讀取，放網站圖片）、`polarisparent_charts`（ASIA-EAST1，未公開）。
- 後端服務帳號：`polarisparent@polarisparent.iam.gserviceaccount.com`。

要新增一個**不公開**的 bucket 放打樣 PDF 與會員照片。在你自己的終端機依序執行（每步後面是成功訊號）：

1. 建立 bucket（台灣附近機房、禁止公開存取、統一權限）：
   ```
   gcloud storage buckets create gs://polarisparent_private --project=polarisparent --location=asia-east1 --uniform-bucket-level-access --public-access-prevention
   ```
   成功訊號：`Creating gs://polarisparent_private/...`，沒有錯誤。
2. 讓後端服務帳號可以讀寫：
   ```
   gcloud storage buckets add-iam-policy-binding gs://polarisparent_private --member=serviceAccount:polarisparent@polarisparent.iam.gserviceaccount.com --role=roles/storage.objectAdmin
   ```
   成功訊號：輸出的 bindings 裡有 `roles/storage.objectAdmin` 和這個服務帳號。
3. 確認沒有公開：
   ```
   gcloud storage buckets describe gs://polarisparent_private --format="value(public_access_prevention)"
   ```
   成功訊號：`enforced`。
4. Railway（pure-grace → polaris-backend → Variables）新增 `PRIVATE_GCS_BUCKET_NAME=polarisparent_private`。產生簽名網址需要服務帳號的私鑰，請一併確認同一個服務的 `GCS_CREDENTIALS_JSON` 已設定；如果沒有，階段 2 開始時再一起處理。
