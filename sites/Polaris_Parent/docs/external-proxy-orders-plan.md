# 外部平台代客建單：設計（待確認）

更新：2026-10-20（第三版，已確認，從第 1 項開始實作）。

## 為什麼要做

網站初期的訂單主要來自小紅書、Etsy、Pinkoi。這些平台嚴格禁止把流量導到站外，客人不會到官網自己下單。實際做法是：**客人在平台成交 → 在平台私訊提供資料 → 管理員在官網後台代客建單 → 後面照官網的標準流程製作與交付**。

目前官網的下單路徑都假設客人本人是會員，而且親自操作。10/14 做的「外部訂單查證＋成交綁定」只能把平台成交對應到客人**自己在官網建好的**待付款訂單，平台售價還必須和官網完全一樣，也只支援單份數位報告，所以套不進這個情境。

## 已確認的決定（2026-10-20）

1. 外部客人在官網有自己的「**客人檔案**」，之後客人可以**認領**。
2. 外部平台以**實體書為主**，部分平台也能賣數位版。
3. 先上**小紅書、Etsy、Pinkoi**。
4. 要記錄每筆資料**來自哪個平台、哪段對話**。
5. 官網要**直接支援多幣別**，不只台幣。
6. Etsy 客人的書可能是**各種語言**（最可能是英文、挪威文或其他歐美語言），製作不能以中文為主。
7. 外部平台的實體書**一律預設精裝**，價格以平台成交金額為準。
8. **只有打樣階段給 PDF**，之後直接出貨實體書，不另外交付數位版。
9. 海外運費先不處理。

## 流程

```
平台成交、私訊取得資料
  → 後台「代客建單」：選客人檔案（或新建）→ 填平台與訂單、客製資料、收件資料 → 附上對話紀錄
  → 官網建立訂單，直接標成「平台已成交」（不建官網付款、不寄信給客人）
  → 自動在 PolarisUI 建工作單 → 編輯接單製作 → 官網後台上傳報告
  → 實體書（主要情境）：編輯做好的書就是打樣 PDF → 你把打樣傳給客人 → 客人在平台回覆 → 你在後台「代為確認」並附上對話紀錄
  → 送印、出貨（登錄物流單號）——客人只會收到實體書，不另外交付數位 PDF
  → 數位版（部分平台）：你從後台下載 PDF，透過平台交給客人，按「已透過平台交付」留下紀錄
```

外部實體書訂單會跳過官網會員用的「設計你的書」：封面名字、題字等由你建單時直接填，建單後實體書直接進入「待出打樣」，也不會出現「待上傳報告」的待辦。

訂單總覽、時間軸、稽核紀錄都照常運作。

## 要做的東西

### 1. 客人檔案

- 每位外部客人一份檔案：平台、平台上的名稱或帳號、聯絡備註。
- 底層是一個**不能登入的會員帳號**，信箱是保留的假網域（`…@customers.polaris-parent.invalid`），寄信會自動略過。命盤因此**依客人分開歸檔**，不會全部掛在你的名下。
- 同一位客人回購時，選既有的檔案就好，舊訂單和命盤都在一起。
- 後台可以搜尋客人、查看他所有的訂單和命盤。

### 2. 代客建單頁（後台）

一頁填完：

| 區塊 | 欄位 |
| --- | --- |
| 平台 | 渠道（小紅書／Etsy／Pinkoi）、平台訂單編號（同一平台不能重複建單）、**平台實際成交金額與幣別** |
| 商品 | 實體書（**預設精裝**，可改規格；數量、封面名字、題字）、數位版、專人解讀 |
| 客製資料 | 主角、性別、出生資料、出生地、讀者、書中稱呼、題字。欄位和驗證跟官網精靈完全一樣，排盤結果一致 |
| 收件 | 實體書的收件人、電話、地址，**加上國家**（Etsy 會有海外客人，目前出貨資料沒有國家欄位） |
| 語系 | 這本書要做的語系（英文、挪威文…任何語言），會一起帶到 PolarisUI 工作單，給語系分工用 |
| 對話紀錄 | 至少一筆：貼上對話文字或連結，或上傳截圖。記錄「這份出生資料是哪天在哪個平台、哪段對話給的」 |

送出前會先**排盤預覽**，跟官網精靈一樣，讓你核對命盤。

### 3. 對話紀錄（資料來源）

- 新增「訂單資料來源」紀錄：平台、對話日期、對話連結或文字摘錄、截圖（存私有儲存，和報告 PDF 同一套）、說明。
- 建單時必填至少一筆；之後也可以隨時追加，例如客人改了收件地址、在平台確認了打樣。
- 「代為確認打樣」可以直接連到某一筆對話紀錄，當作客人同意的證據。
- 這些紀錄只有後台看得到，會出現在訂單詳細頁和時間軸。

### 4. 和既有功能的銜接

- 沿用「外部訂單查證」裡的**渠道設定**（小紅書、Etsy、Pinkoi 各建一個），以及**外部訂單帳本**。平台訂單號因此不會重複建單，每筆都有操作人與依據。
- 訂單標成「平台已成交」，和官網收款分開記錄；**不建立官網付款紀錄**。
- 所有給客人的通知信（訂單成立、報告完成、打樣請確認…）因為是假信箱，會**自動略過**，寄信紀錄標成「已略過（外部客人）」，不會一直重試或發警示。給管理者的通知照寄。
- 新增「已透過平台交付」動作，數位版交付後留下紀錄，讓訂單可以結案。

### 5. 多幣別（第一批的前置工作）

官網目前所有金額都是整數台幣，契約層、外部訂單查證、成交綁定都寫死只接受台幣。要改成：

- 金額一律存「**最小單位**」（台幣是元、美金是分、歐元是分、挪威克朗是 øre），每種幣別記錄小數位數。**現有的台幣資料不用改**，台幣的小數位數就是 0。
- 商品可以設定**多個幣別的售價**（原本的價格表就支援，只是沒用到）。
- 訂單、品項、退款、外部訂單帳本都帶幣別；前台、後台、通知信的金額顯示改成依幣別格式化（NT$1,980／US$49.00／kr 499,00）。
- 第一批先開放：台幣、美金、歐元、挪威克朗、英鎊、人民幣、港幣、日圓；之後要加只要改設定。
- **官網自己的結帳**：目前唯一的收款方式是台幣銀行轉帳。其他幣別要在官網直接結帳，需要先接一個國際金流（例如 Stripe 或 PayPal），這部分要等你選定金流再做。在那之前，**外部平台訂單可以用任何幣別記帳**，官網結帳仍只開台幣。

### 6. 全球出生地（第一批的前置工作）

真太陽時要用出生地的經緯度和時區。目前的出生地資料只有 372 個城市、35 個國家，**北歐、澳洲、愛爾蘭一個都沒有**，Etsy 的歐美客人會選不到出生地。要改成：

- 換成全球城市資料：例如 GeoNames 人口 1.5 萬以上的城市，約 2.6 萬個，每個都有經緯度和 IANA 時區，授權是 CC BY 4.0（要在網站註明資料來源）。
- 城市名稱可以用中文、英文和當地語言搜尋（例如 Tromsø／特羅姆瑟）。
- 後台代客建單另外提供「**手動輸入經緯度與時區**」的備用方式，給清單裡找不到的小鎮使用。
- 官網前台與紫微系統兩邊同步更新，沿用現在的出生地模組和測試（排盤時間與時區的換算方式不變）。

### 7. 翻譯成書＋指定審稿人（PolarisUI，第四項）

2026-10-20 決定：**工作流維持中文**，只在最後把成書翻譯成工作單的語系，再由指定的審稿人審核。

- 中文成書（S5 的 book_document，已驗收）→「翻譯成書」逐段翻譯 → 存成翻譯稿產物（草稿）。
- 帶各語言的紫微**術語表**（星曜、宮位等），整本書同一個詞譯法一致。
- 指定審稿人：中文與譯文左右對照、逐段修改、留意見，按「審核通過」才放行到排版與打樣；只有負責該語系的審稿人能審核。
- 非中文的工作單，翻譯稿沒有審核通過不能標記完成。
- 翻譯模型屆時再換成更強的模型（PolarisUI 目前已不是 SiliconFlow）。
- 2026-10-21 決定：**審稿人按語系指定**（PolarisUI 帳號管理的「可審稿語系」；管理員一律可審）。
- 2026-10-21 已完成（1_run commit 54749263，P_Union 0028）：翻譯稿逐段翻譯（背景執行、可接續）、術語表（英文內建 130 筆）、
  逐段對照審稿與重譯、審核通過另存不可變譯本成書（chart_artifacts kind=book_translation）、非中文工作單沒有通過不能標記完成。
  模型用 `TRANSLATION_MODEL` 切換（預設 deepseek-v4-pro）。
- 尚未做：外文排版（InDesign 出書打包改讀譯本成書、外文字型與版面長度）。

### 8. 認領（第二批）

- 每份客人檔案有一組**認領碼**，你可以在平台上傳給客人。
- 客人之後到官網註冊，在會員中心輸入認領碼，這份檔案的**訂單和命盤就轉到他的正式帳號**，包括 PolarisUI 那邊的命盤歸屬。
- 認領碼只存雜湊、可以作廢重發，用過就失效。

### 9. CSV 批次匯入（第三批）

把平台匯出的訂單一次建成多筆**草稿**。出生資料通常要另外從私訊取得，所以匯入只帶平台、訂單號、金額、商品、收件資料；客製資料由你逐筆補完後才正式建單。

## 分批與工作量（2026-10-20 確認順序）

| 順序 | 內容 | 系統 | 工作量 |

| 2 | 全球出生地（GeoNames 城市資料、多語搜尋、手動經緯度、兩邊同步、網站註明出處） | 官網＋紫微 | 2–3 天 |

## 已確認（2026-10-20 第二輪）

1. 多幣別記帳不需要國際金流；官網外幣結帳等選定金流再做。
2. 報告製作：工作流維持中文，最後節點翻譯＋指定審稿人（見第 7 節）。
3. 全球城市資料用 GeoNames，網站註明出處，加手動經緯度備用。
4. 依上表順序進行，翻譯不提前。

## 不做的事

- 不接任何平台 API、不爬平台資料，也不自動讀取私訊。
- 不判斷平台條款是否允許站外製作；渠道設定只記錄你的審查結果。
- 不做官網外幣結帳（要先選定國際金流）。
- 不做海外運費計算。
