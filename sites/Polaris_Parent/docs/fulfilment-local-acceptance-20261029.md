瀏覽器確認官網登入頁可正常載入；核心交付、版本及下載驗收由真實 HTTP 執行，未宣稱所有頁面均已完成逐按鈕瀏覽器操作。

## 驗收發現及修復

新建代客檔案原先只 flush 尚未 commit，即呼叫製作端。共用資料庫的另一條連線看不到新會員，嘗試同帳號 INSERT 時等待官網交易；官網同時等待 HTTP，最終逾時。

現已先提交通過驗證的客人檔案，再進行跨服務命盤建立；成交認列前重新鎖定並檢查渠道。失敗時可能保留可重用的客人檔案，但不會認列已付款訂單。修正後完整建單／命盤保存／派工實際通過，並補上回歸測試。

## 驗收後接續完成：通知出站重驗

- 報告完成、打樣待確認與打樣提醒，在首次寄送、排程重試、手動重寄時都重新核對資格及暫停狀態。
- 暫停或資格待確認：延後五分鐘再檢查，不消耗 SMTP 嘗試次數；恢復意圖仍需等同步確認。
- 已過期、已回覆、被新版取代的打樣或已沒有可下載報告：停止舊通知。取消／退款及其他既有事件不套用這三類通知的規則。
- 管理員手動重寄遇到業務阻擋回 **409 notification_held**，不再誤標為寄信服務故障。
- 使用同一訂單鎖序列化通知檢查及寄送；已開始的 SMTP 呼叫無法撤回，暫停不追回既有信件。
- 已部署到本機 API，另以真實後台 resend 呼叫驗證 409、pending、嘗試次數 0。合成通知測試結束後清除內文／排程時間並標 skipped，訂單恢復且遠端同步成功。
